- **P0 — An anchor can relocate to unrelated evidence.** Candidate selection searches every indexed document and ranks matches without preferring the original document or source. If the anchored text is removed but a shared block exists elsewhere, the anchor becomes up to date on that unrelated copy, so claims can silently point to the wrong evidence. This behavior is demonstrated by the existing [false-positive test](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/tests/Text_api_tests.ml:1097); the selection and mutation occur in [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348) and [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:490).

- **P1 — Stale anchors are not retried when a destination is indexed later.** Relocation runs only for anchors attached to the document currently being updated. If an anchor becomes stale when its original file changes, then its text appears in a newly indexed file, indexing that new file never revisits the stale anchor. See [Text.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Text.ml:211) and the document-specific query in [DB.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/DB.ml:852).

- **P1 — Repeated text can remain stale even when an exact copy exists.** Shingle indexing discards every occurrence of a 16-byte sequence that repeats within a document; query generation also discards repeated sequences. An anchor made entirely of repeated text therefore has no hits and cannot relocate to an exact copy. The behavior is explicit in [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:152) and covered by the [existing test](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/tests/Anchor_algorithm_tests.ml:102).
