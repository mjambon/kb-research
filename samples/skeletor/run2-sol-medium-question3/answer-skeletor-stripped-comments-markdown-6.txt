I found two **P0** anchor relocation issues:

- **An anchor can silently move to the wrong document.** Candidates are ranked by shingle coverage and hit count, then by lowest document ID; the original document gets no preference ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348)). If two files contain the same anchored text and the original file changes elsewhere, relocation can move the anchor to the older indexed copy even though its text remains in the original file. The anchor then appears up to date while pointing at the wrong evidence.

- **A move between edited files can be missed permanently.** Each file’s anchors are relocated immediately after that file is indexed ([Text.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Text.ml:199)), while bulk updates index files one at a time ([Documents_update_cmd.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/cli/Documents_update_cmd.ml:438)). If the old file is processed before the destination, its new text is absent from the index and the attempt fails. Failed anchors are retried only when their original document’s revision increases ([DB.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/DB.ml:852)); indexing the destination later does not retry them.
