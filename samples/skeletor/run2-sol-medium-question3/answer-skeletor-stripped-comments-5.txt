- **P0 — A routine edit can move an anchor to the wrong document.** Candidates are ranked by shingle coverage, then hit count, then document ID, with no preference for the anchor’s current document. If two files contain the same anchored text and the original file changes elsewhere, the anchor can jump to the lower ID file even though its text remains in place. - **P0 — Relocation depends on file update order.** Each file’s anchors are relocated immediately after that file is indexed. If the source file is processed before the file receiving its text, relocation fails; indexing the destination later does not retry the anchor. This can leave an ordinary cross-file move marked outdated. - **P1 — Short anchors can miss an exact match.** Documents index 16 byte shingles only every eight bytes, while a 16 byte anchor supplies just one query shingle. If an exact copy starts between indexed offsets, relocation has no hit to find, even when the text is unchanged.
