I found three anchor relocation issues:

- **P0 — An anchor can move to unrelated evidence.** Relocation searches every indexed document and selects by text coverage without requiring a connection to the original document. If the original text is removed and another file contains a copy, the anchor becomes current at that unrelated file. The repository has a test documenting this false positive. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348) · [reproduction](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/tests/Text_api_tests.ml:1096)

- **P0 — Cross-document relocation can suppress later review.** Relocation preserves `acknowledged_revision`, although that number belongs to the old document. If an anchor acknowledged at revision 100 moves to a document at revision 1, then later becomes stale there, `needs_review` stays false until that document passes revision 100. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:505) · [review check](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:109)

- **P1 — Short exact matches depend on byte alignment.** Documents index 16-byte shingles only every 8 bytes. A 16-byte anchor moved one byte from an indexed offset has no matching shingle, so relocation leaves it stale even when its text is unchanged. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:152) · [indexing](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:167)
