- **P0 — An anchor can silently move to an unrelated document.** Relocation searches shingles across all indexed documents and selects by text coverage, with no source check or preference for the original document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:355)). If an anchor’s text is removed while a copy already exists elsewhere, the anchor becomes up to date at that copy. The tests confirm this false positive within one source ([Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1096)); the same search also permits it across sources.

- **P0 — Acknowledgment can hide a later relocation failure.** A successful move keeps `acknowledged_revision` from the old document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:505)). `needs_review` then compares that value with the *new* document’s revision ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:109)). For example, an acknowledgment at revision 10 can suppress review when the destination, starting at revision 0, changes and the anchor becomes outdated at revision 1.

- **P1 — Move detection depends on update order.** Each file update relocates only anchors on that file, immediately after indexing it ([Text.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Text.ml:199)). The batch processes changed paths one at a time ([Documents_update_cmd.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/cli/Documents_update_cmd.ml:434)). If the old file is updated before its text is indexed in a destination file, relocation fails; indexing the destination later does not retry the outdated anchor.
