I found three potential issues:

- **P0 — An intact anchor can move to another document.** Candidates are ranked by matched coverage, then hit count, then lowest document ID, with no preference for the original document. If an earlier indexed document has the same text, editing unrelated text in the anchor’s document can move the anchor to that copy even though its original range is intact. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348)

- **P0 — Relocation depends on document update order.** Each file is indexed and its anchors relocated immediately. If the old file is processed before a new destination file, relocation fails; indexing the destination later does not retry the anchor. The same move can therefore succeed or remain outdated depending on file order. [Text.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Text.ml:199), [Documents_update_cmd.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/cli/Documents_update_cmd.ml:438)

- **P0 — An old acknowledgement can hide a later failed relocation.** Relocation preserves `acknowledged_revision` when moving an anchor to another document. If that value exceeds the destination document’s revision, a later failed relocation can be marked `needs_review = false`, omitting it from the review list. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:109), [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:505)
