I found three potential issues with anchor relocation:

- **P0 — An unrelated copy can become current evidence.** Relocation searches all indexed documents and selects by text match, without checking whether the destination is related to the original document. If an anchor’s text is removed while an unrelated file contains the same block, the anchor moves there and becomes up to date. An existing test demonstrates this false positive. See [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348) and [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1098).

- **P1 — Moves between edited files depend on indexing order.** Each file’s anchors are relocated immediately after that file is indexed. If the old file is processed before the destination, the attempt fails; indexing the destination later does not retry anchors still attached to the old file. See [Text.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Text.ml:199), [Documents_update_cmd.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/cli/Documents_update_cmd.ml:438), and [DB.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/DB.ml:852).

- **P1 — Repeated text can prevent relocation even when it matches exactly.** Shingle extraction discards every occurrence of a shingle repeated within a document. For repetitive anchored text, this can leave no hits and mark the anchor outdated despite an exact copy at the destination. The behavior is covered by an existing test. See [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:149) and [Anchor_algorithm_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Anchor_algorithm_tests.ml:102).
