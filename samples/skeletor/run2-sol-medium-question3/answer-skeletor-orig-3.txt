I found three potential issues:

- **P0 — Relocation can suppress future review alerts.** Relocation keeps `acknowledged_revision` when an anchor moves to another document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:505), [DB.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/DB.ml:805)). If the old document was acknowledged at revision 100 and the new document is at revision 0, a failed relocation after edits to the new document will report `needs_review = false` until its revision exceeds 100 ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:109)).

- **P1 — Batch order can leave a moved anchor stale.** Each file is reindexed and its anchors relocated immediately ([Documents_update_cmd.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/cli/Documents_update_cmd.ml:438)). If the old file is processed before the destination, relocation cannot see the destination’s new text. The failed attempt is recorded, and indexing the destination does not retry anchors still attached to the old file ([DB.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/DB.ml:852)).

- **P1 — Matching text can turn unrelated content into current evidence.** Candidate selection has no preference for the original document or proof that text moved ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348)). An existing test demonstrates an anchor relocating to an unrelated file that shares a verbatim block, leaving it marked current ([Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1096)).
