I found two potential issues with anchor relocation:

- **P0 — An anchor can silently move to unrelated content.** Relocation searches every indexed document and chooses the candidate with the most matching shingle coverage, without evidence that the text actually moved there. If the original text is replaced while an unrelated file contains the same boilerplate, the anchor is marked current at that unrelated file. The existing test documents this case. See [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:348) and [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/tests/Text_api_tests.ml:1097).

- **P1 — A failed relocation is not retried when the destination is indexed later.** On failure, the anchor’s attempted revision advances. Relocation subsequently examines only anchors attached to the document being updated. If the old file is updated or deleted before a moved excerpt is indexed in its new file, that later indexing cannot revisit the stale anchor; it remains outdated until the old file changes again. See [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:491) and [DB.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/DB.ml:852).
