I found three potential issues:

- **P0 — An acknowledgment can suppress review after a move to another document.** Relocation preserves `acknowledged_revision` when it changes `doc_id` ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:505)). That revision belongs to the old document, but `needs_review` compares it with the new document’s revision ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:109)). If the new document has a lower revision, a later failed relocation can be outdated yet stay off the review list until its revision exceeds the old acknowledgment.

- **P0 — Matching text can move an anchor to an unrelated document.** Candidate selection has no preference for the original document or evidence that text actually moved ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348)). Replacing an anchor’s text can therefore attach it to another file containing the same block. An existing test demonstrates this known false positive ([Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/tests/Text_api_tests.ml:1096)).

- **P1 — Duplicate text can prevent relocation even when an exact copy exists.** The shingle index discards every occurrence of a shingle that repeats within a document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:152)). An anchor made of duplicated text can consequently have no candidate hits and become outdated after an unrelated edit. The current test records that behavior ([Anchor_algorithm_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/tests/Anchor_algorithm_tests.ml:102)).
