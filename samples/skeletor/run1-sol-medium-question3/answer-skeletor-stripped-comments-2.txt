I found three potential issues:

- **P0 — An unchanged anchor can silently move to the wrong document.** Relocation ranks candidates by text coverage and hit count, then chooses the lowest document ID on a tie, with no preference for the anchor’s current document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348)). If two documents contain the same passage and an edit elsewhere triggers relocation, an anchor can switch to the older document even though its original passage is intact. It is then marked up to date, so a citation can point to the wrong evidence without a review warning.

- **P1 — A move can be missed because relocation runs before the destination is indexed.** The update command indexes files one at a time ([Documents_update_cmd.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/cli/Documents_update_cmd.ml:438)). If it updates the source file before the destination file, relocation finds no match and records a failed attempt ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:490)). Indexing the destination later does not retry that anchor; it remains outdated until its source document changes again.

- **P1 — An old acknowledgement can suppress review after a cross-document move.** Relocation retains `acknowledged_revision` while assigning the destination document’s revision ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:505)). Revisions are per document. If an anchor acknowledged at source revision 10 moves to a destination at revision 0, a subsequent failed relocation at destination revision 1 reports `needs_review = false` because the old acknowledgement still exceeds the new revision ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:108)).
