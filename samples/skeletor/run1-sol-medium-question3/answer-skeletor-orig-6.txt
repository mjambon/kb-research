- **P0 — An unrelated copy can take ownership of an anchor.** Relocation searches every indexed document and chooses the match with the most shingle coverage, with no preference for the anchor’s current document or source ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348)). If the original passage is edited while a longer copy remains elsewhere, the anchor moves to that copy and becomes `Up_to_date`, so claims can point to unrelated code. An existing test demonstrates this false positive.

- **P1 — Indexing order can leave a genuine move stale.** An edit retries only anchors currently assigned to that document ([Text.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Text.ml:211), [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:525)). If the old document is indexed before the destination contains the moved text, the attempt fails. Indexing the destination later does not retry that anchor, even within the same update batch.
