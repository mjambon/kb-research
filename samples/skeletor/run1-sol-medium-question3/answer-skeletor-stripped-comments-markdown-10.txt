I found two anchor relocation issues:

- **P0 — An anchor can jump to an unrelated copy after an edit elsewhere in its file.** Candidates are ranked by text coverage and then document ID, with no preference for the anchor’s current document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348)). If two files contain the same anchored text, editing unrelated text in the original file can move the anchor to the lower-ID file while reporting it as up to date.

- **P0 — Cross-file moves depend on indexing order.** Relocation runs immediately after each document is indexed ([Text.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Text.ml:199)), while a batch indexes files one at a time ([Documents_update_cmd.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/cli/Documents_update_cmd.ml:438)). If the source is processed before the destination, the attempt fails; indexing the destination later does not retry the anchor because stale attempts are selected only when the source document’s revision advances ([DB.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/DB.ml:852)). The anchor can remain outdated after a successful batch update.
