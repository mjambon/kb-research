- **P0 — An anchor can leave its original document even when its exact text is still there.** Candidates are ranked by shingle coverage and then document ID, with no preference for the current document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348)). If an older, unrelated document contains the same text, adding a prefix to the anchor’s document can move the anchor to that copy. The moved anchor is marked up to date and does not need review.

- **P1 — Relocation can depend on document update order.** A failed match is retried only when the anchor’s *current* document gets a new revision ([DB.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/DB.ml:852)). If the source is indexed before the destination during a move, the anchor stays outdated when the destination is subsequently indexed; it will not retry until the source changes again.

- **P1 — Short anchors can fail after a one byte insertion.** Document shingles are stored only at offsets divisible by eight ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:167)). For a 16 byte document and anchor, prepending one byte leaves the exact anchor at offset one, but indexes no shingle from it, so relocation fails.
