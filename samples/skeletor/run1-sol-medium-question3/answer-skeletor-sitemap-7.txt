- **P0 — A move can leave an anchor outdated indefinitely.** After relocation fails, the attempt is recorded against the original document’s revision. Relocation runs only when that document changes, so if the destination file is indexed afterward, the anchor is never retried. This makes the result depend on file indexing order. [Text.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Text.ml:211), [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:490)

- **P0 — An unrelated copy can silently become the anchor’s destination.** Candidates are ranked by text coverage, with no preference for the original document or evidence that a move occurred. Replacing anchored text can therefore make the anchor point to an existing copy in another file and mark it current. A regression test documents this false positive. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:348), [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/tests/Text_api_tests.ml:1097)

- **P1 — Repetitive text cannot relocate even when an exact copy exists.** Shingle extraction discards every occurrence of a repeated shingle, leaving some anchors with no query shingles and thus no candidates. A test confirms that an 80-byte repeated-text anchor stays outdated after moving to an exact copy.
