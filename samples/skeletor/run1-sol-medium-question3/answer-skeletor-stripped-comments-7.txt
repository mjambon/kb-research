- **P0 — An anchor can move away from text that is still present.** Relocation ranks matches by coverage and then document ID, with no preference for the current document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348)). If an earlier indexed document contains the same snippet and the original document changes only outside the anchored range, the tie sends the anchor to the copy. The anchor remains up to date, so this silent change of evidence needs fixing.

- **P1 — A destination indexed later does not rescue a stale anchor.** Relocation runs only for anchors belonging to the document being updated ([Text.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Text.ml:199), [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:525)). A failed attempt records that document’s revision ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:490)). If a move’s destination is indexed afterward, its arrival does not retry the anchor; reindexing the unchanged original also leaves it stale. This can occur when files are processed in that order during one update.
