- **P0 — Moving text between existing files can leave its anchor stale permanently.** [Relocation runs when each document is updated](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Text.ml:199), while [the batch indexes files one at a time](/workspace/kb-research/samples/skeletor/skeletor-orig/cli/Documents_update_cmd.ml:438). If the old file is processed before the destination, relocation fails because the destination’s new text is not indexed yet. Indexing the destination does not retry anchors left on the old file, and an unchanged old file will not trigger another attempt.

- **P0 — An edit outside an anchor can move it to an unrelated duplicate.** [Candidates are ranked by matched coverage, hits, then document ID](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348), with no preference for the anchor’s current document. If an older indexed document contains the same snippet, editing unrelated text in the anchor’s file can make the anchor jump to that duplicate even though its original text remains intact.

- **P1 — Repetitive anchors cannot survive even simple shifts.** [Shingle extraction discards every occurrence of a repeated shingle](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:143). An anchor made entirely of repeated text therefore has no query hits; inserting bytes before otherwise unchanged text marks it outdated. The [existing test](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Anchor_algorithm_tests.ml:100) confirms this behavior.
