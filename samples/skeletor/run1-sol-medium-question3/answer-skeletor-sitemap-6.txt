- **P1 — File moves depend on update order.** Relocation searches the index when the original file is updated ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:483)). If the destination file is indexed later, the attempt is marked failed; indexing the destination does not retry that anchor because it belongs to the original document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:525)). A moved anchor can therefore remain Outdated after a completed batch, depending on file order.

- **P1 — A matching copy can take an anchor from its original file.** Candidates are ranked by shingle coverage and hit count without preferring the original document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:348)). If an edit reduces matches in the original file while another file retains a shared block, relocation can attach the anchor to that unrelated copy, even when the original passage still exists.
