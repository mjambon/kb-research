## Potential anchor relocation issues

- **P0 — An intact anchor can move to the wrong document.** Candidates with equal shingle coverage and hit counts are resolved by the lowest document ID, with no preference for the anchor’s current document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348)). If an older document contains a copy of the anchored text, inserting text before the original anchor can cause it to relocate to that copy even though the original text is still intact. This can silently change what a citation points to.

- **P1 — A failed relocation is not retried when its destination is indexed later.** Relocation runs only for anchors belonging to the document being updated ([Text.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Text.ml:199), [DB.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/DB.ml:857)). If the source is updated before the destination is added, the failed attempt remains outdated when the destination appears; it needs another source revision to be tried again.

- **P1 — Repeated text can leave an exact match unfindable.** Shingle indexing discards *every* occurrence of a shingle repeated within a document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:153)). An anchor made of repeated text can therefore have no searchable shingles and remain outdated despite an exact copy in the index. An existing test documents this behavior ([Anchor_algorithm_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/tests/Anchor_algorithm_tests.ml:102)).
