- **P0 — An unrelated copy can steal an intact anchor.** Candidates with equal coverage and hit counts are ranked by document ID, with no preference for the anchor’s current document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348)). If an earlier indexed document contains the same passage, editing unrelated text in the anchor’s document can move the anchor to that other document even though its original passage is still present.

- **P1 — Repeated text can leave an unchanged anchor outdated.** Indexing discards every occurrence of a 16 byte shingle when that shingle repeats within a document ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:152)). A repeated passage may therefore have no searchable shingles; an edit elsewhere in its file triggers relocation but cannot find the passage. An existing test confirms this behavior for a repeated query ([Anchor_algorithm_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/tests/Anchor_algorithm_tests.ml:102)).

- **P1 — Later indexing of a destination does not retry an outdated anchor.** Relocation considers only anchors attached to the document being updated ([Text.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Text.ml:199), [DB.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/DB.ml:852)). If a passage disappears from one file before its new file is indexed, the first attempt fails. Indexing the new file then leaves the anchor outdated until the old file changes again.
