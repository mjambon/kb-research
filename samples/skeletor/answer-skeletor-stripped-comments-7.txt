When multiple files contain the anchor text, relocation chooses **one** candidate automatically. It ranks candidates by matched text coverage, then by hit count, then by lowest document ID. It gives the original file no preference and does not flag a tie as ambiguous. That is deterministic, but it is risky: identical text does not establish which copy the anchor refers to. The tests already document a false positive where an anchor moves to an unrelated file containing the same block. A safer policy would keep a valid match in the original file and leave equally plausible cross-file matches for review.
