When anchor text matches in multiple files, relocation scores each candidate by matched text coverage, then by the number of matching hits. A tie goes to the **lowest document ID**. There is no preference for the anchor’s original file and no ambiguity warning; the chosen match becomes an up-to-date anchor that does not require review. See [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348) and [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:99).

That is deterministic, but I would not consider it desirable for ambiguous exact matches. A duplicate can be unrelated to the original text, and the [tests document this false positive](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1097). I’d keep the original location when it still matches; if it no longer does and several destinations are equally plausible, mark the anchor for review rather than silently choosing one.
