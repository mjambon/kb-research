When multiple files match the anchor text, relocation chooses **one** candidate. It ranks candidates by matched text coverage, then matching hits, then lowest document ID; it gives no preference to the original file and does not report ambiguity. The chosen location becomes the anchor’s current location. That is deterministic, but it is risky. Identical text in another file may be an unrelated copy, so the anchor can appear up to date while pointing at the wrong evidence. A test documents exactly this false positive. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1097) I would treat indistinguishable matches as ambiguous and require review rather than silently choosing by document ID.
