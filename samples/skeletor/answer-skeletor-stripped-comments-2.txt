When multiple files qualify as relocation candidates, the code picks **one**: highest matched text coverage, then most matching hits, then lowest document ID. It does not flag a tie or prefer the anchor’s original file. The anchor is updated to the selected file and treated as up to date. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348) [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:483)

The deterministic choice is useful, but treating an ambiguous text match as a confident relocation is risky. An existing test documents a false positive: an anchor moves to an unrelated file containing the same text. For equally strong matches, preserving the original file when it still matches, or marking the relocation for review, would better protect the anchor’s meaning.
