When anchor relocation finds plausible matches in multiple files, it **chooses one automatically**: highest matched coverage, then most matching hits, then lowest document ID. It gives the original file no preference and does not flag a tie as ambiguous. The selected anchor is recorded as up to date, with `needs_review = false`. [Candidate ranking](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348) · [Relocation](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:483) · [Status](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:98)

The deterministic choice is useful for repeatability, but **it is unsafe as a correctness decision**: identical text in different files does not establish which occurrence the anchor refers to. A test documents a false relocation onto an unrelated copy. I would prefer the original file when its match remains valid; if multiple other matches remain indistinguishable, leave the anchor for review instead of silently selecting one.
