If anchor text matches multiple indexed files, relocation **chooses one automatically**. It ranks candidates by matched text coverage, then matching hit count, then lowest document ID. The original file gets no preference, even when it still contains the text. The chosen location is recorded as a successful, up-to-date relocation. [Candidate ranking](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348) · [Relocation](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:483)

That is risky for anchors used as evidence: identical text alone cannot establish which copy the anchor refers to. A [test documents the resulting false positive](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1096), where an anchor moves to unrelated boilerplate in another file. I’d prefer an exact match in the original file when one exists; if several other files remain plausible, report the relocation as ambiguous for review instead of silently choosing a file.
