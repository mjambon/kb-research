If the anchor text matches in multiple files, relocation picks **one** candidate automatically. It ranks candidates by matched coverage, then hit count, then lowest document ID; it does not prefer the original file or flag the ambiguity. The selected file becomes the anchor’s new location. That is risky for duplicate text: a deterministic winner is not evidence that it is the *right* copy. The tests already document a false positive where an anchor relocates to unrelated boilerplate in another file. A safer policy would keep an ambiguous anchor unresolved, or require stronger evidence before moving it across files.
