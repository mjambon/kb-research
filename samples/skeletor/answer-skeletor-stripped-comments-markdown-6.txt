When multiple files contain the anchor text, relocation chooses **one** candidate. It ranks candidates by matched text coverage, then by the number of matching hits, then by lowest document ID. It does not prefer the original file or flag a tie as ambiguous. The chosen location is applied automatically. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348)

That is deterministic, but it can be undesirable for an anchor used as evidence: identical text does not establish that the other file is the intended source. A test documents a false positive where an anchor moves onto an unrelated file containing the same block. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/tests/Text_api_tests.ml:1096) A safer policy would retain a valid match in the original file and require review when multiple plausible destinations remain.
