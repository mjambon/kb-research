When anchor text matches in multiple files, relocation chooses **one** candidate: highest matched coverage, then most inlier hits, then lowest document ID. It does not prefer the original file or treat the tie as ambiguous. The anchor is moved to the winner and marked up to date, with no review flag. [Selection code](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348) · [Relocation and status code](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:483)

That is deterministic, but **not desirable for ambiguous copies**. An exact text match cannot establish which file contains the intended evidence. The tests document a case where an anchor moves to an unrelated file containing the same boilerplate as a known false positive. A safer policy would retain an exact match in the original file when possible and require review when several plausible destinations remain.
