If the anchor text matches multiple indexed files, relocation picks **one** candidate. It ranks candidates by matched text coverage, then matching hit count; a tie goes to the lowest document ID. It gives the original file no preference and does not flag the choice as ambiguous ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348), [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:483)).

That is deterministic, but **undesirable for anchors used as evidence**: identical text can appear in an unrelated file, and the anchor can silently move there. The code then treats the relocated anchor as up to date with no review needed ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:98)). A test documents this as a known false positive ([Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/tests/Text_api_tests.ml:1096)). A safer policy would prefer a valid match in the original file and require review when multiple plausible destinations remain.
