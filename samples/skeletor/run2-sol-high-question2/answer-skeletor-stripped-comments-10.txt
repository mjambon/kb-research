The code does not treat multiple exact copies as ambiguous. It ranks candidate files by matched text coverage, then matching hits, then lowest document ID, and relocates the anchor to the winner. It gives the original file no preference. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348)

That is risky for anchors used as evidence: identical text does not show which copy the anchor refers to. The tests already document a false positive where an anchor moves to an unrelated file containing the same block. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/tests/Text_api_tests.ml:1096) A safer policy would keep an exact match in the original file; if it is gone and several destinations remain equally plausible, leave the anchor for review instead of choosing one automatically.
