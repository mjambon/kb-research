When anchor text matches in multiple indexed files, relocation **chooses one automatically**. It ranks candidates by matched text coverage, then by the number of matching hits; if those tie, the lowest document ID wins. The original file gets no preference. The chosen match becomes the anchor’s location and is treated as up to date, with no review flag. [Selection and update code](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348) · [Review status](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:98)

That is deterministic, but **undesirable when the copies are genuinely ambiguous**: document ID does not establish which copy the anchor refers to. The tests document a case where an anchor moves onto unrelated text in another file. A safer policy would keep the original location when it remains a credible match and flag unresolved ties for review.
