If the anchor text matches multiple files, relocation **chooses one file**. It ranks candidates by matched coverage, then matching hits, then lowest document ID. It does not prefer the original file or treat multiple matches as an ambiguity. The chosen anchor is marked up to date with `needs_review = false`. ([selection code](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348), [status code](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:98))

That is risky for an anchor used as evidence: identical text does not establish which copy is the intended destination. The tests already document a false positive where an anchor moves to an unrelated file containing the same boilerplate. ([test](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1096)) I would keep an unambiguous match automatic, but flag equally credible matches for review instead of presenting an arbitrary choice as current evidence.
