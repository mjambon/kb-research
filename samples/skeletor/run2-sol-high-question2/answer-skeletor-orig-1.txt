Relocation considers every qualifying file, then chooses one by matched shingle coverage, inlier hit count, and finally lowest document ID. It does **not** require a unique match or prefer the anchor’s original file. If several files contain the same text, the anchor can therefore move to the wrong one and be treated as up to date. See [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348) and the [documented false-positive test](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1096).

That behavior is undesirable for a persistent reference: identical text alone cannot establish which copy the anchor means. I’d prefer an exact match in the original file when it remains; if it has gone and multiple equally plausible destinations remain, keep the anchor outdated for review rather than choose by document ID.
