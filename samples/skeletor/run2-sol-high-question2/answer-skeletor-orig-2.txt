The relocator chooses **one file automatically**. It ranks candidates by matched text coverage, then by the number of matching hits; if those scores tie, it chooses the lowest document ID. It gives the anchor’s original file no special preference and does not mark the choice as ambiguous. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348)

I don’t think that is desirable when several files are equally plausible. A deterministic choice is useful, but the document ID says nothing about where the text actually moved. The tests already document a case where an anchor relocates to an unrelated file containing a coincidental copy. A safer policy would keep an exact match in the original file when one remains, and flag unresolved matches across files for review. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1098)
