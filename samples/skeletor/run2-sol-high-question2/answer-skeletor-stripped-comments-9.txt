If multiple files are candidates, relocation **automatically picks one**: highest matched text coverage, then most matching hits, then lowest document ID. It gives the original file no preference and does not flag the choice as ambiguous. The selected anchor is recorded as up to date, with `needs_review = false`. See [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348) and [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:483).

That is risky for duplicated text. A deterministic tie break makes the result reproducible, but it cannot establish which copy the anchor was meant to follow. I’d prefer to keep an exact match in the original file when one exists; if only multiple equally plausible destinations remain, report the ambiguity for review instead of silently choosing one.
