If multiple indexed files match the anchor text, relocation **chooses one file automatically**. It ranks candidates by matched text coverage, then by the number of matching hits; a tie goes to the lowest document ID. It does not prefer the original file or flag the ambiguity. That is deterministic, but it is not a reliable way to infer where the *same passage* went. An identical copy in an unrelated file can win and become the anchor’s new location; the tests document a related false positive. For equally strong matches, retaining the original file when it still matches, or leaving the destination for review when it does not, would be safer than choosing by document ID.
