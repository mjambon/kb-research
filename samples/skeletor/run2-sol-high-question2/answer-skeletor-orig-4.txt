When anchor text matches in multiple files, relocation chooses **one** candidate automatically. It ranks candidates by matched text coverage, then matching hit count, then lowest document ID. It gives the original file no special preference, and it does not treat a tie as ambiguous. The selected location becomes the anchor’s current location. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348) [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:483)

The deterministic choice is useful, but silently accepting it is risky: identical text does not establish which copy is the anchor’s intended destination. The tests document a case where an anchor moves to an unrelated file containing the same boilerplate. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1096) I’d treat equally plausible destinations as ambiguous and require review, especially when none is in the original file.
