When the anchor text matches in multiple files, relocation picks **one** candidate automatically. It ranks candidates by matched text coverage, then by the number of matching hits, and finally by lowest document ID. It gives the original file no preference, and updates the anchor to the winner. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348)

That is deterministic, but it can be misleading: identical text in another file does not prove the anchor moved there. A test documents an anchor relocating onto an unrelated copy of shared boilerplate. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/tests/Text_api_tests.ml:1096) For equally plausible matches, I’d prefer retaining the original location when it still matches, or flagging the relocation as ambiguous for review.
