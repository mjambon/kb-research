If the anchor text matches in multiple files, relocation chooses **one** candidate. It ranks candidates by matched text coverage, then matching hit count, then lowest document ID. It does not prefer the original file or treat a tie as ambiguous; the anchor is updated to the winner. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:348) [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:483)

That is deterministic, but it can be undesirable: an equally good copy in an unrelated file may receive the anchor, giving it a misleading location. The tests document a related false positive. A safer policy would prefer an exact match in the original file and surface unresolved cross-file ties for review.
