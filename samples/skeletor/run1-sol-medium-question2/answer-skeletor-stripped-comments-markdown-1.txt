When the anchor text matches in multiple files, relocation **chooses one candidate automatically**. It ranks candidates by matched coverage, then by the number of matching hits; if those tie, it picks the lowest document ID. It gives the original file no preference and does not flag the choice as ambiguous. The anchor is then updated to the selected file and revision. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348)

That is deterministic, but it is **not a reliable way to decide which copy the anchor refers to**. The tests document a known false positive: when the original text is replaced, an unrelated file containing the same block can become the anchor’s destination. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/tests/Text_api_tests.ml:1096) For anchors used as evidence, I would treat equally strong matches as ambiguous and require review, especially before moving one to another file.
