When multiple files contain an exact match, relocation chooses one candidate automatically. It ranks candidates by matched text coverage, then matching hit count, and breaks a tie with the lowest document ID. The original file gets no preference, even if its copy still exists. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348)

That is deterministic, but it is not a reliable way to identify where the *same evidence* went. An unrelated copy can win, causing a false relocation; the tests explicitly document this as a known limitation. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/tests/Text_api_tests.ml:1096) A safer policy would favor a valid match in the original file and leave genuinely ambiguous moves for review.
