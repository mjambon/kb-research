If the anchor text matches in multiple files, relocation **chooses one automatically**. It ranks candidates by matched text coverage, then by the number of matching shingle hits; a tie goes to the lowest document ID. It gives the original file no preference and does not report the match as ambiguous. See [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348) and the [selection step](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:483).

That is deterministic, but generally **undesirable for an evidence anchor**: identical text in another file does not establish that the evidence moved there. The tests document a known false positive where an anchor relocates onto an unrelated copy of shared text ([Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/tests/Text_api_tests.ml:1097)). A safer policy would retain a convincing match in the original file and flag unresolved matches across files for review rather than choosing by document ID.
