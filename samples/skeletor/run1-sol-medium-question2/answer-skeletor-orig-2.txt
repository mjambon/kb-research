When several files contain the anchor text, relocation treats them as candidates and picks one: greatest matched query coverage, then most matching hits, then lowest document ID. It does **not** prefer the original file or report the match as ambiguous. The selected anchor becomes up to date, with no review flag. See [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348) and [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:483).

That is risky for an anchor used as evidence. The tests document a case where it relocates to an unrelated file containing the same text: [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1096). A safer policy would leave genuinely ambiguous matches outdated for review, while still allowing a cross-file move when there is enough evidence to distinguish its destination.
