When multiple files contain the anchor text, relocation chooses **one** candidate. It ranks files by matched shingle coverage, then hit count, then lowest document ID; it gives the original file no preference. The anchor is moved to the winner and marked up to date. That is deterministic, but **undesirable for a persistent reference**: identical text does not establish which copy the anchor meant. The tests document a false positive where an anchor moves to an unrelated file containing the same boilerplate. A safer policy would keep the original location when it remains a valid match and flag genuinely ambiguous moves for review.
