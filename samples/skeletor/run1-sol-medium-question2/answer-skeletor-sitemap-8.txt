When anchor relocation finds matches in multiple files, it ranks the candidates by matched text coverage, then by the number of matching hits, then by lowest document ID. It **takes the first candidate** and updates the anchor to point there. It does not prefer the original file or treat multiple matches as ambiguous. [Candidate ranking](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348) · [Relocation](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:483)

That behavior is risky. An identical copy in an unrelated file can win, even when the anchor’s text still exists in its original file. The tests document relocation to an unrelated copy as a known false positive. A safer policy would keep an intact match in the original file and require stronger evidence, or flag the result for review, when several files remain plausible.
