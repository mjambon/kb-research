When multiple files contain the anchor text, relocation chooses one candidate automatically. It ranks candidates by matched text coverage, then matching shingle hits, then lowest document ID. It does **not** prefer the original file or flag a tie for review. A selected match is recorded as up to date, with `needs_review = false`. [Candidate ranking](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:348) · [Selection](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:483) · [Review status](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:98)

That is deterministic, but **undesirable when the copies could be unrelated**: an anchor can silently move to the wrong file. The tests explicitly document such a false positive. [Known limitation](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/tests/Text_api_tests.ml:1096) A safer policy would flag equally plausible matches as ambiguous and require review before accepting the relocation.
