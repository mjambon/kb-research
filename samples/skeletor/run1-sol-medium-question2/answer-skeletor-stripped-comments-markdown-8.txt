If the anchor text matches in multiple files, relocation chooses **one** destination. It ranks candidates by matched text coverage, then by the number of matching shingles; a tie goes to the lowest document ID. It gives the original file no preference and does not flag the choice as ambiguous. The chosen anchor is then treated as up to date. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348)

That is deterministic, but it is risky for evidence anchors: identical text may be unrelated, so the anchor can silently move to the wrong file. A test documents this as a known false positive. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/tests/Text_api_tests.ml:1096) I would prefer the original file when it still contains the text, and require review when several other files are equally plausible.
