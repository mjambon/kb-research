Relocation considers matches in every indexed file and **chooses one candidate**. It ranks candidates by matched text coverage, then the number of supporting hits, then the lowest document ID. It gives no preference to the anchor’s original file and does not treat multiple matches as ambiguous. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:348) [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:490)

That is deterministic, but it can be undesirable: identical text in several files does not establish which copy the anchor refers to. The tests document a false positive where an anchor moves to an unrelated file containing the same boilerplate. A safer policy would retain the original file when it remains a strong match and flag unresolved cross-file ties for review.
