If multiple files contain the anchor text, relocation ranks their candidates by matched text coverage, then by matching hits, then by lowest document ID. It takes the first candidate even if another is in the anchor’s original file; there is no ambiguity check or original-file preference. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348)

That makes the result deterministic, but it is **not reliably desirable**: an anchor can move to an unrelated copy of the same text. The tests document that false positive. A safer policy would prefer a credible match in the original file and require review when matches across files remain ambiguous. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/tests/Text_api_tests.ml:1096)
