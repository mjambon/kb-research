When multiple files contain the anchor text, relocation considers each as a candidate and **automatically chooses one**. It ranks candidates by matched text coverage, then matching hits, then lowest document ID. It gives the original file no preference, and it does not flag a tie for review. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:348)

That choice is deterministic, but it can be wrong: an unrelated copy may win and silently redirect the anchor. The tests document this as a known false positive. For an ambiguous exact match, I would prefer keeping the original location when it still matches; otherwise, leaving the anchor outdated for review unless other evidence clearly identifies the destination. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/tests/Text_api_tests.ml:1096)
