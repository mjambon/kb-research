If the anchor text matches in multiple files, relocation ranks the candidates by shingle coverage, then hit count. If those scores tie, it chooses the candidate with the lowest document ID. It then moves the anchor there without flagging the ambiguity. [Candidate ranking](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:348) and [relocation](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:483) show this behavior.

That is undesirable when copies of the text are unrelated: an exact match alone cannot establish which file the anchor refers to. The tests document a known false positive where an anchor moves to an unrelated file containing the same block. [Regression test](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/tests/Text_api_tests.ml:1096). Ambiguous matches should be surfaced for review rather than silently resolved by document ID.
