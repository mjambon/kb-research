If the anchor text matches in multiple files, relocation chooses **one** candidate. It ranks candidates by matched text coverage, then by the number of matching hits, and finally by lowest document ID. It gives no preference to the anchor’s original file, even when that file still contains the text. The chosen location is then applied automatically. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348) [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:483)

That makes the result deterministic, but it is **not desirable when the matches are genuinely ambiguous**: document ID cannot tell which copy the anchor refers to. The tests already document a false positive where an anchor moves to an unrelated file containing the same block of text. A safer policy would prefer a valid match in the original file and leave unresolved cross-file ties for review.
