If the anchor text matches in multiple files, relocation selects **one** candidate automatically. It ranks candidates by matched text coverage, then by the number of matching hits, and finally by lowest document ID. The original file gets no preference, and there is no ambiguity check. The selected file becomes the anchor’s location. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:348)

That is deterministic, but it is **not desirable when the copies may be unrelated**: an anchor can move to the wrong file while appearing successfully relocated. The tests explicitly document this false positive. A safer policy would prefer an exact match in the original file and leave ambiguous matches for review when the original text is gone. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/tests/Text_api_tests.ml:1096)
