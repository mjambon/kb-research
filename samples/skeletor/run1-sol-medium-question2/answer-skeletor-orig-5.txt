If multiple files are viable matches, relocation **chooses one**. It ranks candidates by matched text coverage, then by the number of matching hits, then by lowest document ID. It gives the anchor’s original file no special preference and does not mark a tie as ambiguous. The chosen location is stored as the relocated anchor. That is deterministic, but I don’t think it is desirable for genuinely equal matches. Identical text does not establish which copy the anchor was meant to follow. The tests already document a false positive where an anchor moves to an unrelated file containing the same text. A safer policy would retain the original location when it still matches, and flag unresolved cross-file ties for review rather than silently choosing by document ID.
