If multiple files contain the anchor text, relocation ranks the files by matched shingle coverage, then by the number of matching hits. If those scores tie, it chooses the file with the lowest document ID. It does **not** prefer the anchor’s original file, and it applies the chosen relocation automatically. See [candidate ranking](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348) and [relocation](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:483).

The deterministic tie break is useful for repeatability, but it is not evidence that the chosen file contains the *same* passage. For identical copies, silently choosing by document ID can attach an anchor to unrelated text. A safer policy would keep an exact match in the original file when available and flag unresolved matches across files for review. The tests already document a related false positive: relocation onto an unrelated verbatim copy.
