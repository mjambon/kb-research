If the anchor text matches in multiple files, relocation picks **one** candidate. It ranks candidates by matched text coverage, then by the number of matching hits; if those tie, it picks the lowest document ID. It gives the original file no preference and does not mark the result as ambiguous. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348)

That is deterministic, but I would not consider it desirable for genuinely ambiguous matches. The chosen copy may be unrelated to the original anchor, yet relocation updates the anchor to point to it. A test documents this as a known false positive. Prefer the original file when it remains an equally strong match; when several other files remain equally plausible, keep the anchor flagged for review instead of silently choosing by ID. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1097)
