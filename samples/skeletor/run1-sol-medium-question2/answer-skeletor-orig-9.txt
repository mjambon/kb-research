If the anchor text matches in multiple files, relocation **chooses one candidate automatically**. It ranks candidates by matched text coverage, then by the number of supporting hits, and finally by lowest document ID. It gives the original file no special preference, even when that file still contains the text. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348) [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:483)

The deterministic choice is useful, but silently moving an anchor to one of several plausible copies is risky: identical text does not establish which copy the anchor was meant to follow. The tests already document a case where it moves to an unrelated file containing the same block. I’d prefer to keep an exact match in the original file when available, and flag ambiguous cross-file matches for review rather than pick by document ID.
