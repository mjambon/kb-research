When anchor text matches in multiple indexed files, relocation chooses **one** candidate automatically. It ranks candidates by matched text coverage, then by the number of matching shingle hits, then by lowest document ID. It gives the original file no preference and does not flag a tie as ambiguous. The chosen location is written to the anchor. [Ranking and selection](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348) · [Relocation write](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:483)

That is deterministic, but **not reliably desirable for evidence anchors**: identical text does not establish which file the evidence belongs to. The tests document a known false positive where an anchor moves to an unrelated file containing the same passage. A safer policy would prefer a credible match in the original file and leave unresolved cross-file ties for review.
