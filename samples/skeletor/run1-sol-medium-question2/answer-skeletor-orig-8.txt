If the anchor text matches in multiple files, relocation chooses **one** candidate automatically. It ranks candidates by matched shingle coverage, then by hit count, then by lowest document ID. The original file gets no preference. The chosen location becomes the anchor’s current location, with no review flag when relocation succeeds. That is risky when the text is copied or boilerplate: an exact match alone cannot establish which file contains the intended reference. The tests document a case where an anchor moves to an unrelated copy. I would treat equally plausible matches as ambiguous and require review, rather than silently choosing by document ID.
