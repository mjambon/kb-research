When multiple files contain the anchor text, relocation picks **one candidate automatically**. It ranks candidates by matched text coverage, then by the number of matching shingles; a tie goes to the lowest document ID. It does not prefer the anchor’s original file or flag the ambiguity for review. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348)

That gives a deterministic result, but it can attach an anchor to the wrong file. A test documents exactly this false positive: an anchor relocates to an unrelated file containing the same boilerplate. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/tests/Text_api_tests.ml:1096) For genuinely ambiguous matches, leaving the anchor outdated for review would be safer than silently choosing a destination.
