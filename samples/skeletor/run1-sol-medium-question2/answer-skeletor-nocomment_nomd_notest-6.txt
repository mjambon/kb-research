The relocator does **not** treat matches in multiple files as ambiguous. It ranks candidates by matched text coverage, then by the number of matching shingles, then by lowest document ID, and moves the anchor to the top candidate. It gives the original file no preference. See [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:348) and [the relocation step](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:483).

That is deterministic, but it is **not desirable when the copies may mean different things**: identical text alone cannot establish which file contains the original evidence. The tests document a case where an anchor moves to an unrelated file containing the same text. A safer policy would keep an exact match in the original file; if several other files remain equally plausible, it should flag the anchor for review instead of silently choosing one. See [the known limitation test](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/tests/Text_api_tests.ml:1096).
