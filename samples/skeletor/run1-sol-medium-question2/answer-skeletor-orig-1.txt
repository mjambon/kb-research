If the anchor text matches in multiple files, relocation **chooses one automatically**. Candidates are ranked by matched text coverage, then the number of matching hits; a tie goes to the lowest document ID. There is no preference for the original file and no ambiguity check. The chosen anchor becomes up to date, so it does not require review. See [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348) and [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:483).

That is deterministic, but I don’t think it is desirable for equally good matches. Identical text does not establish which copy the anchor refers to; the repository already documents a case where an anchor moves to an unrelated copy in another file ([test](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1097)). When evidence cannot distinguish destinations, keeping the anchor outdated for review would be safer than silently selecting by document ID.
