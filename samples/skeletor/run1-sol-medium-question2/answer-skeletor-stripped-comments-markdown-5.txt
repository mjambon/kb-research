When the anchor text matches in multiple files, relocation **chooses one file automatically**. It ranks candidates by matched text coverage, then by the number of matching hits, then by lowest document ID. It gives the original file no preference, so even an exact match there can lose a tie and the anchor can move to another file. The chosen location is written to the anchor. [Selection code](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348) · [Relocation code](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:483)

That is deterministic, but **undesirable for genuinely ambiguous matches**: identical text alone cannot establish which copy the anchor refers to. The tests already document a false positive where an anchor moves to an unrelated file containing the same block. A safer policy would retain the original file when it still has an equally good match, and otherwise flag tied matches for review instead of silently choosing one.
