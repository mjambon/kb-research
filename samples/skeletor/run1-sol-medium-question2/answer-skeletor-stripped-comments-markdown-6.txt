If the anchor text matches in multiple files, relocation chooses **one** candidate. It ranks candidates by matched text coverage, then by the number of matching hits; a tie goes to the lowest document ID. The original file gets no preference, so the anchor can move to a different file even when the text still exists in its original file. That is deterministic, but it is risky for evidence anchors: identical text does not establish which file the anchor refers to. A test already documents a false positive where an anchor moves onto unrelated boilerplate. [Known limitation](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/tests/Text_api_tests.ml:1096) A safer policy would prefer a valid match in the original file and leave genuinely ambiguous cross-file matches for review.
