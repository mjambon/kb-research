Anchor relocation picks **one file**. It ranks candidates by matched text coverage, then by the number of matching hits; a tie goes to the lowest document ID. It does **not** prefer the anchor’s original file or flag multiple matches as ambiguous. The chosen location is saved as an up-to-date anchor ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348), [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:483)).

That deterministic tie break is useful for repeatability, but **silently choosing among identical copies is undesirable**: the text alone cannot establish which file contains the intended evidence. A test already documents relocation onto an unrelated copy as a known false positive ([Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/tests/Text_api_tests.ml:1096)). Prefer the original file when its match remains valid; when only multiple equally plausible new files remain, mark the anchor for review.
