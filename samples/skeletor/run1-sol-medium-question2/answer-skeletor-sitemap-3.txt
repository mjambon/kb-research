If anchor text matches in multiple files, relocation chooses one candidate automatically. It ranks candidates by matched text coverage, then matching hits, then lowest document ID; it gives the original file no preference. An exact tie can therefore move an anchor to another file for an arbitrary reason. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-sitemap/src/skeletor/base-libs/text/Anchor.ml:348)

That is deterministic, but generally undesirable: identical text does not establish that the anchor moved. The tests document a case where an unrelated copy of the text is chosen. A safer policy would keep a valid match in the original file and treat unresolved matches across files as ambiguous, requiring review.
