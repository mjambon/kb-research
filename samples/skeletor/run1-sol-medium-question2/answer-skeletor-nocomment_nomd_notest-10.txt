If multiple files contain the anchor text, relocation ranks their candidates by matched text coverage, then by the number of matching shingle hits. If those scores tie, it chooses the lowest document ID. It does **not** prefer the original file or flag the tie as ambiguous; it updates the anchor to the selected file. That is deterministic, but it is not reliably desirable. Identical text in two files cannot establish which copy is the intended evidence. The tests already document a case where an anchor moves to an unrelated file containing the same block. A safer policy would prefer a credible match in the original file and leave genuinely ambiguous cross-file matches for review.
