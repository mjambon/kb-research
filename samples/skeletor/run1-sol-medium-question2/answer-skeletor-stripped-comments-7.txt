If multiple files qualify as relocation matches, the code **chooses one automatically**. It ranks candidates by matched text coverage, then by the number of matching hits, then by lowest document ID. It gives the anchor’s original file no preference and does not flag a tie as ambiguous. The chosen location is written to the anchor. [Candidate ranking](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348) · [Relocation](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:483)

The deterministic result is useful, but **automatic relocation on an ambiguous exact match is undesirable for evidence anchors**: identical text does not establish which file the anchor refers to. The tests already document a case where an anchor moves to an unrelated file containing the same text. A safer policy would keep an exact match in the original file when available and require review when multiple plausible destinations remain.
