If anchor text matches in multiple files, relocation picks **one** candidate: the one with the most matched text coverage, then the most matching shingle hits, then the lowest document ID. It gives the original file no preference, even on a tie, and updates the anchor to the selected file. The relocated anchor can then appear up to date with no review required. ([selection logic](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:348), [status logic](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:98))

That is risky for ambiguous text. An unrelated file can receive the anchor simply because it contains the same passage; the tests document this as a known false positive. A safer policy would prefer an equally strong match in the original file and require review when multiple files remain plausible. ([known limitation](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/tests/Text_api_tests.ml:1096))
