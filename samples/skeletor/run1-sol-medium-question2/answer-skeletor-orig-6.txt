When anchor text matches in multiple files, relocation chooses **one** candidate. It ranks candidates by matched text coverage, then by the number of matching hits, then by lowest document ID. It gives the original file no preference and does not flag a tie as ambiguous. The anchor is updated to the chosen file and marked current. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348) [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:483)

That is undesirable for genuinely ambiguous matches: a coincidental copy can become the anchor’s destination and appear to be valid evidence. A test documents this as a known false positive. A safer policy would keep an exact match in the original file when available and require review when a move has multiple equally plausible destinations.
