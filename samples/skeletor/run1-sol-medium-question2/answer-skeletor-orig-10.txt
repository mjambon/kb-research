If several indexed files contain the anchor text, relocation does **not** treat that as ambiguous. It chooses one candidate by matched shingle coverage, then hit count, then lowest document ID. The original file gets no preference, and the anchor is updated to the winner. “Exact match” has no separate priority in this ranking. [Candidate ranking](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348) · [Relocation update](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:483)

That is deterministic, but risky for evidence anchors: identical text cannot establish which copy is the intended one. A [test documents a false relocation](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1096) onto unrelated duplicated text. I would prefer the original file when it still has a valid match; if multiple other files remain equally plausible, leave the anchor for review rather than silently choosing by document ID.
