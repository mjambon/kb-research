When the anchor text appears in multiple files, relocation picks **one candidate**. It ranks candidates by matched shingle coverage, then by the number of matching hits, then by lowest document ID. It does not prefer the anchor’s original file or flag the choice as ambiguous. An exact copy can therefore cause an anchor to move to an unrelated file. ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:345), [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:483))

That is deterministic, but **not desirable as a claim of where the original text went**: identical text alone cannot establish which copy is the right destination. I’d prefer the original file when it still contains a suitable match, and treat equally plausible matches in other files as ambiguous and needing review. The tests already document a related false positive where relocation chooses an unrelated copy. ([Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/tests/Text_api_tests.ml:1097))
