If multiple files are valid relocation candidates, the anchor is **automatically assigned to one**. The matcher ranks candidates by matched text coverage, then matching hits, then lowest document ID. It gives the original file no preference ([Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:346), [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:483)). For otherwise equal exact matches, that last tie breaker decides the destination.

That is deterministic, but it is risky: identical text in another file does not establish that the anchor moved there. The tests document a case where it relocates onto an unrelated copy ([Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/tests/Text_api_tests.ml:1097)). I would treat equally strong matches as ambiguous—prefer the original location when it still matches, and otherwise leave the anchor for review rather than silently choosing a file.
