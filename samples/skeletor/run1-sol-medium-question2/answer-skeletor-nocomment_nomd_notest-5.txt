If multiple files contain the anchor text, relocation picks **one** candidate. It ranks candidates by matched text coverage, then by the number of matching shingles; a tie goes to the lowest document ID. The original file gets no preference. The anchor is then updated to point to the selected file as current evidence. ([ranking](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:348), [update](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/Anchor.ml:483))

That is deterministic, but **not desirable for ambiguous exact matches**: identical text does not establish which copy the anchor refers to. The tests already document a case where an unrelated copy becomes the destination. A safer policy would prefer an intact match in the original file and leave unresolved cross-file ties for review. ([known limitation](/workspace/kb-research/samples/skeletor/skeletor-nocomment_nomd_notest/base-libs/text/tests/Text_api_tests.ml:1097))
