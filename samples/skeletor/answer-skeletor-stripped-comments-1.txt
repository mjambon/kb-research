If the anchor text matches in multiple files, relocation chooses **one** candidate. It ranks candidates by matched text coverage, then by the number of matching shingle hits, then by lowest document ID. It gives the original file no special preference and does not flag a tie as ambiguous. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/Anchor.ml:348)

That is deterministic, but it can be undesirable: identical text in unrelated files can cause an anchor to move to the wrong file and appear up to date. The tests document this as a known false positive. A safer policy would prefer a valid match in the original file and require review when equally strong matches remain across files. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments/base-libs/text/tests/Text_api_tests.ml:1097)
