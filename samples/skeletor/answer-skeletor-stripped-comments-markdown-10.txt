Relocation picks **one file automatically**. It ranks candidates by matched coverage, then the number of matching hits, then lowest document ID. It gives the original file no preference and does not report the result as ambiguous. The winning file becomes the anchor’s new location. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/Anchor.ml:348)

That is useful when text has genuinely moved, but **undesirable when several files contain the same text**: the ranking cannot establish which copy the anchor meant. An unrelated copy can be selected and treated as current; the tests document this as a known false positive. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-stripped-comments-markdown/base-libs/text/tests/Text_api_tests.ml:1096) A safer policy would preserve a matching original location when possible and flag unresolved ties for review.
