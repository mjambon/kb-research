If multiple files qualify as relocation candidates, **the anchor moves to one file**. The code ranks candidates by matched shingle coverage, then by hit count, then by lowest document ID. It gives the original file no special preference. This is a heuristic, so identical text does not necessarily receive an identical score in every file. [Anchor.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/Anchor.ml:348)

I don’t think silently choosing on a tie is desirable for an anchor used as evidence. A copy of the text may be unrelated to the original, yet the anchor is treated as successfully relocated. The tests document this as a known false positive. A safer policy would prefer the original location when it still matches and flag genuinely ambiguous moves for review. [Text_api_tests.ml](/workspace/kb-research/samples/skeletor/skeletor-orig/base-libs/text/tests/Text_api_tests.ml:1096)
