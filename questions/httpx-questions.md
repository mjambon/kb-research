## Question 1

When an HTTPX Client follows a redirect, when is the Authorization
header retained or removed? Explain the same-origin rule and the
HTTP-to-HTTPS exception, and cite the relevant symbols and tests.

## Answer 1 (sol high: 24s)

HTTPX retains `Authorization` on a redirect **if the destination has the same origin, or qualifies for the HTTP-to-HTTPS exception**. Otherwise, it removes the header. This is implemented in [`BaseClient._redirect_headers`](/workspace/kb-research/samples/httpx/httpx/_client.py:546), which copies the request headers and conditionally calls `headers.pop("Authorization", None)`.

- **Same origin:** scheme, host, and effective port must all match. Paths and query strings do not matter. [`_same_origin`](/workspace/kb-research/samples/httpx/httpx/_client.py:83) compares those three fields, using [`_port_or_default`](/workspace/kb-research/samples/httpx/httpx/_client.py:77) to treat omitted ports as HTTP 80 or HTTPS 443. Thus, `https://example.org/a` → `https://example.org:443/b` retains authorization.
- **HTTP-to-HTTPS exception:** [`_is_https_redirect`](/workspace/kb-research/samples/httpx/httpx/_client.py:62) allows authorization to survive an upgrade from **HTTP port 80 to HTTPS port 443 on the same host**, with default ports either explicit or omitted. An upgrade involving a different host or nondefault ports does not qualify.
- **Other origin changes:** changing hosts, changing effective ports, or downgrading HTTPS → HTTP removes authorization.

The relevant tests in [`tests/client/test_redirects.py`](/workspace/kb-research/samples/httpx/tests/client/test_redirects.py:266) are:

| Test | What it verifies |
|---|---|
| [`test_same_domain_redirect`](/workspace/kb-research/samples/httpx/tests/client/test_redirects.py:292) | Same-origin redirect retains the header. |
| [`test_same_domain_https_redirect_with_auth_header`](/workspace/kb-research/samples/httpx/tests/client/test_redirects.py:301) | Same-host HTTP → HTTPS upgrade retains it. |
| [`test_cross_domain_redirect_with_auth_header`](/workspace/kb-research/samples/httpx/tests/client/test_redirects.py:266) | Cross-host redirect removes it. |
| [`test_cross_domain_https_redirect_with_auth_header`](/workspace/kb-research/samples/httpx/tests/client/test_redirects.py:275) | HTTP → HTTPS still removes it when the host changes. |
| [`test_cross_domain_redirect_with_auth`](/workspace/kb-research/samples/httpx/tests/client/test_redirects.py:284) | Cross-host stripping also applies to authorization generated by `auth=("user", "pass")`. |

The port-change and downgrade conclusions follow directly from the helper conditions; these five tests do not separately exercise those cases.


## Question 2

How does HTTPX Timeout distinguish an omitted timeout from None?
Explain scalar defaults, per-operation overrides, and the condition
that raises ValueError. Cite source and tests.

## Answer 2 (sol high: 27s)

`Timeout` uses a private `UNSET` sentinel as the default for the scalar `timeout` and each of `connect`, `read`, `write`, and `pool`. That lets it distinguish an **omitted** argument from an explicit `None`. `Timeout(None)` sets all four operations to `None`, disabling their timeouts; the tests check this directly. [Source](/workspace/kb-research/samples/httpx/httpx/_config.py:16) · [Tests](/workspace/kb-research/samples/httpx/tests/test_config.py:113)

A scalar such as `Timeout(5.0)` supplies the default for every operation. An explicitly supplied operation value replaces that default, including `None`: `Timeout(5.0, pool=None)` disables only the pool timeout. Tests also verify `Timeout(5.0, pool=60.0)` and `Timeout(None, read=5.0)`. [Source](/workspace/kb-research/samples/httpx/httpx/_config.py:127) · [Tests](/workspace/kb-research/samples/httpx/tests/test_config.py:126)

`ValueError` is raised when the scalar default is omitted **and** at least one of the four operation values is omitted. Supplying all four explicitly is valid; `Timeout(pool=60.0)` is the tested error case. [Source](/workspace/kb-research/samples/httpx/httpx/_config.py:111) · [Tests](/workspace/kb-research/samples/httpx/tests/test_config.py:108)
